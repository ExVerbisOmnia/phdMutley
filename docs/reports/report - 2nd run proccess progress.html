Executive Summary

High-level overview of the v7 pipeline development effort — 9 days, 8 sessions, 52 issues tracked

Project Status

The phdMutley citation extraction pipeline reached v7.0 production readiness after 9 days of intensive development (1–9 Mar 2026). The pipeline processes 4,724 judicial decisions from the Climate Case Chart database, extracting and verifying transnational citation patterns between Global North and Global South courts. A full-dataset extraction is currently 31% complete on a GCP VM, running at 16.5 docs/min with a 94.9% citation confirmation rate.

The most consequential finding was that the v6 extraction prompt caused 49.3% hallucinated citations due to Knowledge Base contamination. This was resolved by removing the KB from the prompt entirely and adding three hard filters (pipe-format, anachronism, snippet-must-exist). The v7 pipeline now achieves <5% unconfirmed citations across all verification categories.

Hallucination & Accuracy 5 issues

Root cause: Knowledge Base contamination in extraction prompt caused 49.3% fabricated citations

Root Cause

The v6 extraction prompt included 4,741 case names from the Sabin knowledge base (~150K tokens). The LLM "extracted" KB entries that were topically related but not actually cited in the document. This is associative hallucination, not extraction.

Evidence

Claude Chat manual verification of 1,410 citations: 695 REJECTED (49.3%). 467/695 rejections (67.2%) had pipe | delimiter — Sabin metadata format, not judicial citation format.

Fix Applied

KB entirely removed from extraction prompt. Sabin filter continues to run post-extraction for ID linking and name standardization only. File: extraction_prompt_v6.py

Source: Plan Step 1D · claude-chat-verification-run-output.xlsx

Hard filter detects (Year) | Court; Jurisdiction pattern in raw_citation_text. Citations matching this pattern are moved to citation_extraction_discarded with reason PIPE_FORMAT_METADATA.

File: extract_citations.py · Function: is_pipe_format()

Hard filter rejects citations where cited_year > document_year + 1. A 2021 document cannot cite a 2023 case. +1 year tolerance for delayed publication.

File: extract_citations.py · Function: is_anachronistic()

25/574 pipeline-CONFIRMED citations were actually REJECTED on manual review. E.g., "Wells" matching "exploratory wells", "EPA" in generic human rights text.

Fix: Verification prompt hardened — context-aware matching required (footnotes, "see also", case law sections), not just keyword presence.

File: citation_verification.py · Verification prompt enhancement

54 citations (3.8%) exist under wrong names. KB has separate entries for related cases and the LLM confuses them. Normalized name matching in Sabin filter.

Source: Plan Step 1D · CORRECTED bucket in manual verification

VM Runtime Issues VMISSUE-1–4

Issues from 500-document test on VM (e2-standard-16, 16 vCPU, 64 GB) and full-dataset run

Escalation: 1 → 6 → 32 NULLs over the 500-doc run (2.6% final). Pattern is systemic — the verification LLM's JSON response simply omits some citations.

Fix: Default unverified citations to UNVERIFIED status. Any citation not updated by verification response gets this fallback.

File: citation_verification.py:~356

3/500 documents failed with "Phase 2A extraction failed - no result returned". Processing times (27–42s) suggest multiple retry attempts. Likely safety filter or malformed JSON.

Fix: Enhanced logging with text_len. Failed docs can be retried with lower concurrency.

Distinct from VMISSUE-1: This covers entire Phase 5 failure (no LLM response at all), not individual citation omissions. With --concurrent 10, rate limit exhaustion causes RuntimeError after 5 retries.

Fix: Added UNVERIFIED fallback in the except block of Phase 5 in extract_citations.py. Pre-fix NULLs (94 citations) to be fixed post-run with SQL UPDATE.

Root Cause

--concurrent 10 with many large docs (>50K chars) hitting Gemini Flash 1M tokens/min quota. Retry logic (2s base backoff) amplified the storm — multiple workers retrying simultaneously.

Escalation Path

—concurrent 10 → killed, —concurrent 5 → still failing → —concurrent 3 → still failing → switched to Pro → Pro also daily-capped → pipeline paused

Fix

Updated gemini_client.py: parse API's retryDelay from 429 errors, use 15s base backoff (was 2s), cap at 120s max. Switched to prolifico-edu project API key for fresh quota.

Key Design Decisions

Architectural choices shaping the v7 pipeline — each driven by empirical findings

Problem: 4,741 case names in the prompt (~150K tokens) caused the LLM to fabricate citations by topical association. 49.3% hallucination rate.

Decision: Strip KB entirely from extraction prompt. The Sabin filter runs post-extraction for ID linking and name standardization — this preserves research utility without contamination.

Trade-off: Slightly reduced recall for obscure case names vs. dramatically improved precision.

Before: Separate post-hoc verification script (Phase DQ). Orphaned unverified citations possible.

After: Phase 0 (quality pre-check) → 1 (jurisdiction) → 2A (extraction) → Hard filters → Sabin filter → 2B (classification) → 3 (origin) → 4 (sixfold) → 5 (inline verification). No citation left unverified.

RoleModelThinkingRationale
Extractiongemini-2.5-flash1024High-volume, cost-sensitive; Flash is 10x cheaper than Pro
Classificationgemini-2.5-pro2048Complex reasoning for court/jurisdiction mapping
Origin IDgemini-2.5-pro1024Disambiguation requires deeper reasoning
Verificationgemini-2.5-flash1024Pattern matching task; Flash sufficient

Docker added complexity for a single-user research project. Native PG18 on port 5433 avoids port conflict with Aegis's Docker PG on 5432. Simpler ops, fewer dependencies, faster startup.

Created text_quality.py (garbled/length checks) and citation_verification.py (shared verification logic). Imported by both extract_citations.py and verify_citations.py.

Gemini 2.5 thinking mode improves reasoning quality for classification and verification. Added thinking_budget parameter to gemini_client.py. Token tracking includes thinking tokens in cost calculations.

4 documents exceed 2M chars (~1.1M tokens), beyond Gemini's 1M token context. Marked SKIPPED_TOO_LONG with requires_manual_review=TRUE. Affects 286 citations (2.4%). Future options: Gemini 2.5 Pro (larger context), chunking, or manual review.

At ~$0.009/doc, cost is negligible. Rather than waiting for daily quota reset (midnight Pacific), switch to a fresh project's API key. Three keys tested; prolifico-edu key is active.

Balances throughput vs. rate limit risk. Improved backoff (15s base, API-suggested delay, 120s cap) prevents retry storms. 23 rate limit retries in 1,450 docs — all recovered successfully. ETA for 4,724 docs: ~4.5 hours.
