How to Answer — Pipeline & DB Capabilities

Q1 — Top Citing Jurisdictions

Data source: citation_extraction_phased + citation_extraction_phased_summary + documents + cases

Approach

-- Per document, count DISTINCT foreign decisions cited (not textual repetitions) → D16 -- Aggregate by source jurisdiction → rank countries -- Express as % of total identified citations → D17 (relative proportions)

What We Have

  • citation_extraction_phased has individual citations with source_jurisdiction (the citing court) and cited_jurisdiction (the cited court)
  • The sixfold classification in citation_sixfold_classification already tags each citation's direction type (foreign, international, etc.)
  • We can query distinct (document_id, cited_case) pairs grouped by source country

Gap: The 275 failed docs (~5%) are missing — acceptable for Monday if flagged as a limitation.

Q2 — Most Paradigmatic Cases (Most-Cited)

Data source: Same tables, flipped perspective

Approach

-- Count how many DISTINCT documents cite each foreign case → rank by citation count -- Map cited cases to their jurisdictions → shows geographic reach -- Bonus: network visualization showing origin → destination

What We Have

  • citation_extraction_phased stores the cited case name/reference per citation
  • We can group by cited case, count distinct citing documents, and rank
  • The cases table has jurisdiction metadata to map geographic spread
  • The analysis engine (sixfold_analysis_engine.py) already produces network data for D3.js — section 7 (network graph data) likely covers this

Challenge: Cited case names may have variations (e.g., "Urgenda" vs "Urgenda Foundation v. State of the Netherlands"). The Sabin filter / knowledge base (build_knowledge_base.py) was built exactly for this — normalizing case references against known cases.
